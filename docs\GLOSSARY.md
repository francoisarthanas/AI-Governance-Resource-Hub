# Working Glossary

Use definitions from applicable law or standards when they govern. This glossary is for internal consistency, not legal interpretation.

| Term | Working meaning |
|---|---|
| AI system | A machine-based system that infers from inputs how to generate outputs—such as predictions, content, recommendations, decisions, or actions—that can influence physical or virtual environments |
| AI model | A computational component that produces inferences; it is not the whole socio-technical AI system |
| Use case | The specific purpose, context, users, affected parties, workflow, and decision/action in which AI is used |
| General-purpose AI model | A broadly capable model usable across a wide range of tasks; apply the governing jurisdiction's definition |
| Generative AI | AI that generates content such as text, image, audio, video, code, or structured data |
| AI agent | A software-based component that perceives inputs, maintains state, selects actions, and uses tools to pursue a goal within assigned permissions and constraints |
| Agentic AI system | One or more agents plus orchestration, models, memory, data, tools, policies, humans, and environment that perform multi-step work with some autonomy |
| Autonomy | The degree to which a system selects and executes actions without contemporaneous human decision |
| Delegated authority | The bounded authority a principal gives an agent to act; it should preserve identity, purpose, scope, duration, and accountability |
| Tool | A function, API, application, device, browser, code executor, data source, or other capability an agent can invoke |
| MCP | Model Context Protocol, an application-level protocol used to connect AI applications with tools and context sources |
| A2A | Agent2Agent Protocol, an open protocol for communication and collaboration between agents |
| Memory | State retained across turns or tasks; may include working context, short-term state, or persistent long-term records |
| Human-in-the-loop | A human participates before or during a decision/action and can approve, change, or reject it |
| Human-on-the-loop | A system acts while a human supervises and can intervene; meaningfulness depends on visibility, time, competence, and authority |
| Impact assessment | A structured process to identify affected parties, benefits, harms, rights, risk, controls, residual impact, and monitoring across the lifecycle |
| AI/ML-BOM | A machine-readable bill of materials for models, datasets, code, services, configurations, dependencies, and provenance |
| TEVV | Testing, evaluation, verification, and validation |
| Red teaming | Authorized adversarial testing to discover failures, misuse, vulnerabilities, or control weaknesses |
| Evaluation | A defined method for measuring system behavior or outcomes against requirements in a stated context |
| Guardrail | A preventive, detective, or corrective constraint; prompt instructions are only one weak form |
| Policy decision point | A component that evaluates principal, action, resource, and context against deterministic policy |
| Residual risk | Risk remaining after controls; it must be owned and accepted at the authorized level or further treated |
| Material change | A change capable of altering impact, obligations, risk, controls, or evidence enough to trigger re-review or retest |
| AI incident | An event in which AI development, use, or malfunction leads directly or indirectly to harm; use regulator-specific definitions where applicable |
| AI hazard | A condition or event that could plausibly lead to an AI incident |
| System card | A structured record of the complete AI system's purpose, context, components, behavior, risks, controls, tests, limits, owners, and operation |
| Model card | Documentation focused on a model's intended uses, performance, limitations, and evaluation |
| Data card | Documentation focused on a dataset's origin, composition, collection, processing, use, limitations, and governance |
| Provenance | Traceable information about the source and history of data, model, content, component, or decision artifact |
| Drift | Change in data, context, behavior, performance, or outcomes relative to the approved baseline |
| Contestability | The ability of affected people to understand, challenge, correct, appeal, or obtain remedy for a result |
| Shadow AI | AI acquired, built, connected, or used outside the organization's approved visibility and control paths |

Primary vocabulary references: [OECD AI Principles](https://oecd.ai/en/principles), [ISO/IEC 22989](https://www.iso.org/standard/74296.html), [NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework), and applicable law.
